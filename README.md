# PingPongRally

강사가 QR 하나로 교육생을 모아 질문(**핑**)을 던지고 답(**퐁**)을 실시간으로 주고받는 강의용 웹앱입니다.
설계서: [`etc/PingPongRally 설계서.md`](etc/PingPongRally%20설계서.md)

- **교육생**: 설치·가입 없이 QR/입장 코드 → (사전 설문) → 닉네임 → 랠리. PC에서는 강사 화면처럼 왼쪽 핑 목록 + 오른쪽 핑·퐁, 휴대폰에서는 지금 핑 중심에 ‹ › 이동과 [전체] 목록
- **이모지 반응**: 퐁마다 👍 👎 ❤️ 😂 😮 🤔 를 누를 수 있고, 같은 이모지를 두 명 이상 누르면 작은 숫자로 개수가 붙는다
- **참석자 등록**: 설문처럼 따로 받는다. 강사가 등록 링크를 단체 대화방·문자·메일로 보내면 참석자가 미리 등록하고, 강의 당일 같은 휴대폰으로 입장하면 자동으로 이어진다
- **강사**: Google로 로그인(비밀번호 없음) → 강의 1개 만들기 → [강의 시작] → 핑 포커스 → 퐁·리플 → 퀵폴·설문 → 종료·내보내기
- **강사 화면은 두 탭**: [진행]은 핑 목록·포커스·답 보기만, [관리]는 강의 정보·참석자 등록·설문과 설문 템플릿·핑 템플릿·내보내기
- **빠르게 만들기**: [추가] 한 번에 핑·퀵폴·템플릿 탭이 있는 창이 바로 열린다. 화면을 캡처해 `Ctrl+V` 하면 그 이미지로 핑(강사)·퐁(교육생) 창이 열린다. 퀵폴 선택지는 [예/아니오]·[2]~[5] 버튼으로 한 번에 채운다
- **발표 화면**: 보드 뷰 / 네트워크 뷰(핑→퐁→리플 방사형), QR·입장 코드, 퀵폴·설문 결과
- **자동 파기**: 글·파일은 시작 72시간 뒤, 등록·설문 정보는 종료 7일 뒤

## 바로 실행해 보기 (데모 모드)

```bash
npm install
npm run dev
```

`.env`에 Supabase 값이 없으면 **데모 모드**로 실행됩니다. 데이터는 브라우저(IndexedDB)에만 저장되고, 같은 브라우저의 다른 탭과 실시간으로 동기화됩니다.

| 해 볼 것 | 방법 |
| --- | --- |
| 교육생으로 입장 | 처음 화면에서 코드 `777777` 입력(또는 아래 데모 링크) |
| 강사로 로그인 | `/host` → [데모 강사 계정으로 둘러보기]. [Google로 계속하기]를 누르면 데모에서는 **빈 새 계정**으로 들어가요 |
| 참석자 등록 링크 | 데모 강의의 등록 링크 `/reg/c0ffee7a11e7` ([관리] 탭 → [참석자 등록] → [참석자에게 보내기]) |
| 핑 추가·템플릿 | [진행] 탭 핑 목록의 [추가] → 핑 / 퀵폴 / 템플릿. 핑의 ⋯ → [템플릿으로 저장] |
| 이모지 반응 | 퐁 아래 웃는 얼굴 버튼 → 이모지 선택. 다른 탭(강사·교육생)에도 바로 반영돼요 |
| 캡처 붙여 넣기 | 화면을 캡처(Win+Shift+S 등)한 뒤 강사 [진행] 화면이나 교육생 랠리 화면에서 `Ctrl+V` |
| 1인 1강의 | 열린 강의가 있으면 [새 강의 만들기]가 사라지고, 강제로 만들려 해도 서버가 막아요(하루 3개까지) |
| 교육생 여러 명 | 탭마다 다른 교육생이 됩니다. 새 탭에서 `777777`로 다시 입장 |
| 실시간 동기화 | 한 탭은 강사 [진행] 화면, 다른 탭은 교육생 화면을 띄우고 [포커스] |
| 북적이는 강의 | [진행] 화면 오른쪽 [데모: 가상 교육생 들이기] → 8명이 퐁·리플·투표·설문 |
| 발표 화면 | [진행] 화면 [발표 화면] → 단축키 `1` 보드, `2` 네트워크, `Q` QR, `F` 전체 화면, `+`/`-` 글자 |

데모 데이터를 처음 상태로 되돌리려면 강사 화면 오른쪽 위 계정 메뉴의 **[데모 데이터 초기화]**를 누르세요.

## 구조

```
src/
  lib/
    backend/        화면이 쓰는 Backend 인터페이스
      supabase.ts   운영: supabase-js (RLS가 최종 권한 판단)
      demo/         데모: IndexedDB + BroadcastChannel, 예시 데이터, 가상 교육생
    hooks.ts        useRoomState / useRoomEvents (실시간 + 재연결 증분 조회 + 폴링 폴백)
    export/         ZIP·Markdown(JSZip), 엑셀(ExcelJS), 핑 템플릿 파일 가져오기
  components/       디자인 시스템(ui/), 랠리·설문·강사 화면 부품
  pages/            교육생(rally/), 강사(host/), 발표(present/) 화면
supabase/
  migrations/       테이블 10개 · RLS · 서버 함수 · 실시간 · 스토리지
  functions/purge/  파기 Edge Function (Storage API로 파일 삭제)
  cron.sql          pg_cron 예약 작업
  tests/            PGlite 로 마이그레이션·RLS 91개 항목 검증
scripts/loadtest.mjs  가짜 교육생 60~100명 부하 테스트
.github/workflows/keepalive.yml  3일마다 호출(일시정지 방지)
```

화면 12개(설계서 14장)에 [관리] 탭(`/host/rooms/:id/manage`)과 핑 템플릿 묶음 편집기(`/host/ping-sets/:id`)를 더했습니다. 강사·발표 화면과 React Flow·Recharts·ExcelJS·JSZip은 필요할 때만 불러와, 교육생 첫 화면은 JS 약 125KB(gzip)입니다.

## 운영 배포 (Supabase + Cloudflare Pages)

### 1. Supabase 프로젝트

1. 새 프로젝트를 **서울(ap-northeast-2)** 리전에 만듭니다.
2. **SQL Editor**에 `supabase/migrations/20261123000000_init.sql`을 붙여 넣고 실행합니다. (CLI: `supabase link` 후 `supabase db push`)
3. **Authentication → Sign In / Providers**
   - **Allow new users to sign up 켜기** — 강사는 Google 첫 로그인이 곧 가입입니다(아래 ‘강사 로그인’ 참고)
   - **Google 켜기**: Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보에서 OAuth 클라이언트 ID(웹 애플리케이션)를 만들고, 승인된 리디렉션 URI에 `https://<프로젝트>.supabase.co/auth/v1/callback`을 넣은 뒤 Client ID·Secret을 Supabase에 붙여 넣습니다. OAuth 동의 화면은 ‘외부’·게시 상태로 둡니다
   - **Email 끄기** — 이메일·비밀번호로 계정을 만드는 길을 닫습니다(강사는 Google만)
   - **Anonymous sign-ins 켜기** (교육생)
4. **Authentication → URL Configuration**: Site URL에 배포 주소, Redirect URLs에 `https://<배포 주소>/host/login**`를 넣습니다.
5. **Authentication → Rate Limits**: 익명 로그인 한도를 시간당 30 → **300 정도**로 올립니다(교육장 와이파이는 IP 하나).
6. (권장) **Attack Protection → CAPTCHA**에 Cloudflare Turnstile 비밀 키를 넣습니다. 사이트 키는 아래 `VITE_TURNSTILE_SITE_KEY`에. 교육생 익명 입장·참석자 등록이 봇 확인을 거칩니다.

### 2. 파기 함수와 예약 작업

```bash
supabase functions deploy purge --no-verify-jwt
supabase secrets set PURGE_SECRET=<긴 임의 문자열>
```

그다음 Dashboard에서 `pg_cron`, `pg_net` 확장을 켜고 `supabase/cron.sql`의 `<...>`를 채워 실행합니다.
- 10분마다 만료된 강의 종료, 매시간 파기(글·파일 72시간 / 개인정보 종료 7일 / 10일 지난 빈 익명 계정)

### 3. Cloudflare Pages

| 항목 | 값 |
| --- | --- |
| Build command | `npm run build` |
| Output directory | `dist` |
| 환경 변수 | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, (`VITE_TURNSTILE_SITE_KEY`), `VITE_STORAGE_LOCATION` |

`404.html`이 없으므로 Pages가 SPA로 처리합니다. 보안 헤더는 `public/_headers`에 있습니다.

### 4. 일시정지 방지

GitHub 저장소 **Settings → Secrets → Actions**에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 넣으면 `.github/workflows/keepalive.yml`이 3일마다 `keepalive()`를 호출합니다.

## 강사 로그인과 강의 개수 제한 — 검토와 결정

**결론: 강의를 여는 사람은 로그인이 필요하다. 방법은 Google 로그인 하나로 단일화한다(비밀번호 없음, 첫 로그인이 곧 가입).**

| 왜 로그인이 필요한가 | 설명 |
| --- | --- |
| ‘1명당 1강의’를 지키려면 | 로그인 없이는 사람을 구분할 기준이 브라우저 저장소나 IP뿐이다. 시크릿 창·브라우저 정리로 바로 우회되고, 교육장·기관은 와이파이 IP 하나를 여럿이 쓴다 |
| 봇 차단 | 익명으로 강의를 만들 수 있으면 스크립트로 무한히 만들 수 있다(무료 한도 소진) |
| 개인정보 보호 | 강사는 참석자 성명·소속을 본다. 계정 없이 링크만으로 열람하게 하면 링크 유출이 곧 개인정보 유출이다 |
| 여러 기기 | 노트북·휴대폰·발표 PC에서 같은 강의를 다루려면 계정이 있어야 한다 |

| 방법 | 판단 |
| --- | --- |
| **Google 로그인** | ✔ 채택. 설정이 간단하고 메일 발송 비용·SMTP가 필요 없다. Google 계정은 대량으로 만들기 어려워 봇 차단에 유리하다 |
| 카카오 로그인 | 제외(사용자 결정). 비즈 앱 전환·동의 항목 설정 부담 |
| 이메일 인증 코드 | 제외(사용자 결정). 일회용 메일로 계정을 여러 개 만들 수 있고, 메일 발송 서비스(SMTP)가 필요하다 |
| 관리자 발급 이메일·비밀번호 | 제외. 관리자가 일일이 발급해야 한다 |

**봇·중복 생성 막기(여러 겹)** — 모두 DB에서 강제하므로 API를 직접 불러도 우회되지 않는다.
1. 강사 계정 1개당 **열린(준비·진행) 강의 1개** — 부분 고유 인덱스 `rooms_one_open_per_host` + 트리거. 종료하거나 준비 중인 강의를 지우면 새로 만들 수 있다
2. **24시간에 3개까지** 생성 — `room_creations` 기록(지워도 남음)으로 ‘만들고 지우기’ 반복을 막는다
3. 강사 계정은 Google로만 생긴다(Email 공급자 끔). 익명 계정은 강의를 만들 수 없다(RLS)
4. 강의를 만들 때 상태·코드·시각은 서버가 정한다(클라이언트가 `live`로 바로 만드는 것 차단)
5. 핑 템플릿 묶음·설문 템플릿은 계정당 100개, 등록은 강의당 1,000명까지
6. 문제 계정은 Supabase 대시보드 **Authentication → Users → Ban user**로 막는다

**입장 코드는 숫자 6자리**(100000~999999, 사용자 요청). 휴대폰 숫자 자판으로 바로 넣을 수 있고 `123 456`처럼 띄어 써도 된다. 영문·숫자 조합보다 경우의 수가 적어(90만 개) 마구 넣어 보기를 막는다: 틀린 코드를 **10분에 20번** 넘게 넣은 계정은 잠시 입장 조회·입장이 막힌다(`code_attempts`, `check_code_attempts`). 교육생 익명 로그인 자체도 Turnstile과 IP별 한도를 거친다.

교육생은 지금처럼 로그인 없이(화면 없는 익명 계정) 입장한다.

## 템플릿 — 다시 쓰는 핑과 설문

- **핑 템플릿**: [진행] 탭 [추가] 창의 [템플릿] 탭에서 여러 개를 골라 한 번에 넣는다. 저장은 ① 핑을 만들 때 [내 템플릿에도 저장], ② 핑의 ⋯ → [템플릿으로 저장], ③ [관리] → [핑 템플릿] → [이 강의 핑 모두 저장]. 하나씩 저장한 것은 ‘내 템플릿’ 묶음에 모이고, 강의 전체 저장은 강의 제목으로 묶인다. 파일(.json)로 가져오고 내보낼 수 있다. 저장소는 기존 `ping_sets` 테이블을 그대로 쓴다
- **설문 템플릿**: [관리] → [설문 템플릿]에서 만들고 고친다. [관리] → [설문] → [붙이기]로 사전·중간·사후 설문으로 붙인다
- 템플릿은 계정에 남고, 강의 기록이 파기돼도 지워지지 않는다. 올린 파일은 강의와 함께 지워지므로 핑 템플릿에는 링크 첨부만 남는다

## 참석자 등록 — 설문처럼 링크로 보내기

1. 강의를 만든 뒤 **[관리] 탭 → [참석자 등록] → 등록 폼 만들기**: 개인정보처리자·문의처·휴대폰 수집 여부만 정하면 링크(`/reg/xxxxxxxxxxxx`)가 생긴다
2. **[참석자에게 보내기]**: 안내 문구 복사 · 공유(휴대폰) · 메일 · 등록 QR. 강의 전날 단체 대화방에 보내거나 당일 화면에 QR을 띄운다
3. 참석자는 링크에서 소속·부서·성명 + 동의 → 끝. 강의 시작 전에도 할 수 있다
4. 강의 당일 **같은 휴대폰**으로 입장 QR을 찍으면 등록과 닉네임이 자동으로 이어진다(같은 익명 계정). 다른 기기로 들어온 사람에게는 랠리 화면에 ‘참석자 등록을 부탁드려요’ 한 줄이 뜬다
5. [참석자 명단]에서 등록·입장 여부, 사전 명단 대조, 출석부 엑셀. 마감·다시 열기 가능. 강의를 종료하면 자동 마감
6. 등록 정보는 강의 종료 7일 뒤 파기. 강의를 시작하지 않은 채 남으면 폼을 연 지 30일 뒤 강의째 파기

| 공식 업무 / 개인 도구 | 둘 다 쓸 수 있게, 강의마다 개인정보처리자·문의처를 입력 |
| 개인정보처리자·문의처 | [관리] → [참석자 등록] 설정에서 입력 → 동의 문안에 자동 반영(바뀌면 문안 버전 +1) |
| 리플 명칭 | ‘리플’ 유지 |
| 퀵폴 결과 공개 | 기본은 마감 후. 퀵폴마다 ‘실시간 공개’를 켤 수 있음 |
| 강의 연장 | 한 번에 1~24시간, 시작 후 최대 48시간까지 |
| 서술형 설문 발표 공유 | 기본 비공개. 강사가 결과 화면에서 문항을 골라 띄울 때만 표시 |

## 설계서와 다르게 구현한 부분

- **참석자 등록을 입장에서 분리**(사용자 요청): 등록 모드(필수·선택·끄기) 대신 `rooms.registration`(off·open·closed)과 등록 링크 토큰 `rooms.reg_token`을 둔다. 입장은 `join_room(code, nickname)`, 등록은 `register_by_token(token, …)`로 나뉜다
- **강사 로그인**: 관리자 발급 이메일·비밀번호 → Google 로그인 하나(가입 겸용). 위 ‘검토와 결정’ 참고
- **강사 1명당 열린 강의 1개, 하루 3개**: 위와 같음
- **화면 용어와 구성**: ‘강의실’ 대신 ‘강의’. 강사 화면은 [진행]·[관리]·[참석자 명단]·[설문 결과] 탭, 대시보드의 핑 세트·설문 템플릿 탭은 없애고 [관리] 탭과 [추가] 창의 [템플릿] 탭으로 옮김
- **퐁 이모지 반응 추가**(사용자 요청): `node_reactions`(사람마다 퐁 하나에 한 행, 고른 이모지 배열)와 `toggle_reaction`·`my_reactions` 함수. 개수는 `nodes.meta.reactions`에 모아 두어 기존 nodes 실시간 채널로 퍼진다. 퐁·리플을 만들 때 meta 는 서버가 비우고, 작성자도 반응 개수를 직접 바꿀 수 없다
- **디자인**: 가는 글꼴(Pretendard 350, 굵게는 최대 500), 1px 선, 그림자·그라데이션 없이 단순하게

- **`rooms`를 참여자가 직접 읽음**: 공개 컬럼만 담긴 뷰는 Postgres Changes를 받을 수 없어서, 개인정보가 없는 `rooms` 행을 입장한 참여자도 읽게 했습니다(포커스 실시간 수신용). 상태·코드·시각 컬럼은 열 단위 권한으로 막고 서버 함수로만 바꿉니다.
- **`nodes.opened_at` 추가**: 미리 준비한 핑은 강사가 처음 [포커스]할 때 교육생에게 공개됩니다(정답을 미리 엿보지 않도록).
- **`rooms.moderation_rev` 추가**: 숨긴 글은 RLS 때문에 교육생에게 실시간 이벤트가 가지 않으므로, 숨김 때 이 번호를 올려 교육생 화면이 목록을 다시 받게 했습니다.
- **`rooms.present` 추가**: 발표 화면 상태(보드/네트워크, QR 표시, 띄운 설문 문항)를 강사 [진행] 화면과 발표 화면이 함께 씁니다.
- **작성자는 자기 숨김 글을 읽을 수 있음**: Postgres는 UPDATE 결과 행도 SELECT 정책을 통과해야 하므로, 이게 없으면 교육생의 ‘삭제(숨김)’가 막힙니다(`test:db`로 확인).

## 공식 교육에서 쓰기 전에 (설계서 6.6)

동의 문안은 초안이며 법률 검토를 대신하지 않습니다. 개인정보처리자, 해외 사업자 클라우드 이용·처리위탁 고지, 공공기관 클라우드 이용 기준(CSAP 등)을 주관 기관 개인정보·정보보호 담당 부서와 확인하세요. 기관에 출석 관리 시스템이 있으면 등록을 ‘끄기’로 운영하는 것이 가장 간단합니다.
