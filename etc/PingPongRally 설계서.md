# PingPongRally 설계서

Nov 23, 2026 · @크루

## 1. 개요

PingPongRally는 강사가 QR 하나로 교육생을 모아 질문(핑)을 던지고 답(퐁)을 실시간으로 주고받는 강의용 웹앱이다. 강의실은 강의 시작 후 24시간 동안 열리고, 무료 클라우드 한도 안에서 운영한다.

- **대상**: 공공기관 AI 교육 강사, 모바일로 접속하는 교육생, 강의장 대형 스크린
- **핵심 가치**: 설치·회원가입 없이 30초 안에 참여, 강사가 지금 다루는 핑을 모두의 화면에 띄움, 주고받은 내용을 네트워크로 한눈에 보여 줌
- **포함 범위**: 강의실 생성·QR 입장, 참석자 등록(개인정보 동의), 핑·퐁·리플, 퀵폴, 설문조사, 발표 화면·네트워크 뷰, 내보내기(ZIP·Markdown·엑셀), 자동 파기
- **이번 버전 제외**: 화상·음성, AI 자동 요약, 기관 SSO 연동, 유료 결제
- **운영 원칙**: 무료 티어 유지, 개인정보 최소 수집, 정해진 기간이 지나면 자동 삭제

## 2. 용어 정의

화면과 코드는 같은 용어를 쓴다. DB의 `type` 값도 아래 영문 이름을 따른다.

| 용어 | 코드 값 | 뜻 | 만드는 사람 |
| --- | --- | --- | --- |
| 강의실 | `room` | 강의 1회분의 공간. 입장 코드·QR로 들어옴 | 강사 |
| 핑 | `ping` | 강사가 던지는 질문·화두. 글·이미지·파일·링크 첨부 | 강사 |
| 퐁 | `pong` | 핑에 대한 답 | 교육생(강사도 가능) |
| 리플 | `reply` | 퐁에 다는 댓글. 리플에 리플은 없고 @닉네임으로 이어 씀 | 모두 |
| 랠리 | — | 핑 하나에서 이어진 퐁·리플 묶음 전체 | — |
| 포커스 | `active_ping_id` | 강사가 지금 다루는 핑. 교육생 화면이 따라감 | 강사 |
| 퀵폴 | `poll` | 강의 중 즉석 투표. 핑의 한 종류 | 강사 |
| 설문지 | `survey` | 미리 만들어 둔 여러 문항 설문. 사전·중간·사후 | 강사 |
| 핑 세트 | `ping_set` | 강의마다 다시 쓰는 핑 묶음 템플릿 | 강사 |
| 참석자 등록 | `participant` | 기관·부서·성명(·휴대폰) 입력과 개인정보 동의 | 교육생 |

리플 명칭은 17장 결정 사항에 남겨 두었다.

## 3. 사용자와 권한

강사는 이메일 계정으로, 교육생은 화면 없는 익명 로그인으로 들어온다. 두 방식 모두 서버가 사용자를 구분하므로 권한 규칙(RLS)을 걸 수 있다.

| 역할 | 접속 방법 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- | --- |
| 강사 | 이메일·비밀번호 로그인. 공개 가입은 막고 관리자가 대시보드에서 발급 | 강의실 생성·시작·연장·종료, 핑·퀵폴·설문 관리, 포커스 지정, 글 숨김, 출석·설문 결과 열람, 내보내기 | 다른 강사의 강의실 접근 |
| 교육생 | QR 또는 입장 코드 → 익명 로그인(자동) → 등록·닉네임 | 퐁·리플 작성, 본인 글 수정·삭제, 투표, 설문 응답, 본인 등록 정보 확인·삭제 | 핑 작성, 포커스 변경, 다른 사람 등록 정보 조회 |
| 발표 화면 | 강사 로그인 상태에서 `/present` 열기 | 네트워크 뷰·보드 뷰, QR·입장 코드, 퀵폴 결과 표시 | 입력·조작 |

- 강사 권한은 계정에 붙어 있어 노트북·휴대폰 어느 기기에서나 같다. 4자리 PIN 방식은 쓰지 않는다(노출·무차별 대입 위험).
- 교육생은 같은 브라우저로 다시 열면 세션이 유지되어 등록을 반복하지 않는다. 기기를 바꾸면 새 참석자로 등록되며, 사전 명단 대조로 중복을 확인한다.
- 랠리 화면에는 닉네임만 보인다. 성명·소속은 강사 화면에서만 볼 수 있다.

## 4. 사용 흐름

교육생은 QR 하나로 랠리 화면까지 들어오고, 강사는 전날 준비부터 자동 파기까지 6단계로 진행한다.

### 4.1 교육생 입장

&#91;embedded content: 교육생 입장 흐름 · 판단 3곳\]

끄기 모드는 등록을 건너뛰고, 선택 모드에서 등록을 거부하면 등록 없이 사전 설문으로 넘어간다. 필수 모드에서 거부하면 입장이 막힌다.

### 4.2 강사 진행 순서

1. **전날 준비**: 강의실 생성(준비 상태), 핑 세트 불러오기·핑 작성, 설문지 붙이기, 등록 모드·휴대폰 수집 설정, 사전 명단 업로드(선택)
2. **강의 시작**: \[강의 시작\]으로 입장 코드·QR을 활성화하고 발표 화면을 띄운다.
3. **진행**: 핑 포커스 → 퐁·리플 함께 보기 → 다음 핑. 필요하면 퀵폴·중간 설문을 열고, 부적절한 글은 숨긴다.
4. **마무리**: 사후 설문을 열고 \[강의 종료\]를 누른다. 누르지 않으면 시작 24시간 뒤 자동 종료된다.
5. **정리**: 종료 후 48시간 안에 ZIP·Markdown·출석부·설문 결과를 내려받는다.
6. **자동 파기**: 시작 72시간 뒤 글·파일이, 종료 7일 뒤 등록·설문 정보가 지워진다.

## 5. 기능 명세

핵심은 강사가 핑을 포커스하면 모든 교육생 화면이 그 핑으로 넘어가고, 교육생은 버튼 하나로 퐁을 보내는 것이다.

### 5.1 강의실

- **생성 설정**: 제목, 등록 모드(필수·선택·끄기), 휴대폰 수집 여부, 핑 세트·설문지 붙이기, 사전 명단 업로드(선택)
- **상태**: 준비(`draft`) → 진행(`live`) → 종료(`closed`). 준비 중에는 강사만 들어가 핑을 미리 작성한다.
- **시작**: \[강의 시작\]을 누르면 입장 코드·QR이 활성화되고, 만료 시각은 시작 + 24시간으로 정해진다.
- **입장 코드**: 영문 대문자·숫자 6자리. 헷갈리는 문자(0·O, 1·I)는 빼고, 진행 중인 강의실끼리 겹치지 않게 한다.
- **연장·종료**: 강사가 만료 시각을 늦추거나 \[즉시 종료\]할 수 있다. 연장 범위는 17장에서 정한다.

### 5.2 핑·퐁·리플

- **핑**: 강사만 작성한다. 본문에 이미지·파일·링크를 여러 개 붙일 수 있고, 핑별로 \[퐁 마감\]을 켤 수 있다.
- **포커스**: 강사가 핑에서 \[포커스\]를 누르면 교육생 화면이 그 핑으로 바뀐다. 교육생이 글을 쓰는 중이면 화면을 넘기지 않고 “새 핑으로 이동” 배너만 띄운다.
- **퐁**: 현재 핑 아래 \[퐁 보내기\]. 본문 최대 1,000자, 첨부는 핑과 같다.
- **리플**: 퐁 카드를 누르면 리플 입력창이 열린다. 리플에는 다시 리플을 달 수 없고, 답할 사람을 @닉네임으로 표시한다.
- **수정·삭제**: 본인 글만 수정·삭제한다. 강사는 모든 글을 \[숨김\] 처리할 수 있다. 삭제는 모두 숨김(UPDATE)으로 처리해 실시간 반영을 단순하게 한다.
- **첨부 규칙**: 이미지는 자동 압축(원본 가로 1,280px, 썸네일 400px), 문서는 10MB 이하, 실행 파일 차단, 링크는 http·https만 허용한다.
- **한글 입력**: Enter 전송 시 `isComposing`을 검사하고, 전송 중에는 버튼을 잠가 같은 글이 두 번 올라가지 않게 한다.

### 5.3 퀵폴

- 투표형 핑이다. 선택지 2\~6개, 단일·복수 선택, 1인 1표(마감 전까지 변경 가능).
- 강사가 \[투표 시작\]·\[마감\]을 누른다. 결과는 발표 화면에 막대그래프로 2초마다 갱신한다.
- 누가 어디에 투표했는지는 강사에게도 보이지 않는다. 교육생에게 결과를 언제 보여 줄지는 17장에서 정한다.

### 5.4 보기 모드

| 화면 | 기기 | 보여 주는 것 |
| --- | --- | --- |
| 피드 뷰 | 교육생 휴대폰 | 현재 핑 + 퐁 카드 목록(최신순·리플 많은 순), 다른 핑 골라 보기 |
| 강사 제어판 | 강사 노트북·휴대폰 | 핑 목록·포커스, 퀵폴·설문 열기, 출석 현황, 숨김, 연장·종료, 내보내기 |
| 발표 화면 | 강의장 스크린 | 큰 글씨, QR·입장 코드 상시 표시, 보드 뷰와 네트워크 뷰 전환, 퀵폴 결과 |

- **네트워크 뷰**: 핑 → 퐁 → 리플 3단을 d3-hierarchy로 방사형 배치한다. 핑을 누르면 그 가지만 강조하고 나머지는 흐리게 한다. 노드에는 두 줄 요약과 썸네일만 넣고, 누르면 상세 패널이 열린다.
- **필터**: 핑별, 첨부 유형(이미지·파일·링크), 키워드 검색. 강의실 데이터는 수백 건 수준이라 브라우저에서 걸러낸다.
- React Flow와 배치 코드는 발표 화면에서만 불러와(lazy import), 교육생 화면을 가볍게 유지한다.

## 6. 참석자 등록과 개인정보 동의

등록은 강의실마다 필수·선택·끄기 중 하나로 정하고, 성명 등 개인정보는 동의를 받은 뒤에만 저장한다. 등록 정보는 본인과 강사만 볼 수 있고 교육 종료 7일 후 자동 파기한다.

### 6.1 등록 화면 항목

| 항목 | 구분 | 입력 방식 | 비고 |
| --- | --- | --- | --- |
| 소속 기관 | 필수 | 텍스트. 사전 명단이 있으면 기관명 자동완성 |  |
| 부서 | 필수 | 텍스트 |  |
| 성명 | 필수 | 텍스트 |  |
| 휴대폰 번호 | 선택 | 010-0000-0000 형식 검사 | 강의실 설정에서 켜야만 표시. 선택 동의를 체크해야 입력란이 열림 |
| 닉네임 | 필수 | 텍스트, 2\~12자 | 랠리 화면에 보이는 이름. 등록 정보와 분리 저장 |
| 필수 항목 동의 | 필수 | 체크박스 | 체크 전에는 \[등록\] 버튼 비활성 |

### 6.2 등록 모드별 동작

| 모드 | 등록 화면 | 필수 동의를 거부하면 | 어울리는 강의 |
| --- | --- | --- | --- |
| 필수 | 입장 전 반드시 표시 | 이 강의실에 참여할 수 없다는 안내 표시 | 출석 확인이 필요한 정규 과정 |
| 선택 | 표시하되 \[등록 없이 참여\] 제공 | 닉네임만으로 참여. 출석은 확인되지 않음 | 출석이 있으면 좋은 특강 |
| 끄기 | 표시 안 함 | 해당 없음 | 짧은 특강, 기관이 출석을 따로 관리하는 교육 |

개인정보 없이 소속 분포만 알고 싶다면, 등록을 끄고 익명 사전 설문에 ‘소속 기관 유형’ 객관식 문항을 넣는다.

이 문안은 초안이며 법률 검토를 대신하지 않는다. 공식 교육에서 쓰기 전 주관 기관 개인정보 담당 부서의 검토를 받고, 보유 기간은 기관의 출석 자료 보관 기준에 맞춘다.

### 6.4 저장·열람·파기 규칙

- 등록 정보는 `participants` 테이블에 따로 저장하고, 랠리 글에는 닉네임만 연결한다.
- 열람은 본인과 그 강의실의 강사만 가능하다(RLS).
- 동의 기록으로 문안 버전, 필수 동의 시각, 선택 동의 시각을 함께 저장한다. 문안을 고치면 버전을 올린다.
- 휴대폰 번호는 화면·엑셀에서 기본 가림(010-\*\*\*\*-1234) 처리하고, 강사가 \[전체 보기\]를 눌러야 보인다.
- 교육 종료 7일 후 자동 파기하고, 강사는 \[지금 파기\]로 앞당길 수 있다. 교육생이 \[내 정보\]에서 삭제하면 즉시 지운다.
- 내려받은 출석부 엑셀은 파일명에 ‘개인정보 포함’을 붙이고, 내려받기 전에 보관·삭제 안내를 표시한다.

### 6.5 사전 명단 대조(선택)

- 강사가 명단 엑셀(기관·부서·성명·휴대폰 뒤 4자리)을 올리면, 등록할 때 성명과 뒤 4자리(없으면 기관+성명)로 자동 매칭한다.
- 강사 화면은 출석·미출석·명단 외 참석자 세 가지로 나눠 보여 주고, 출석부를 엑셀로 내보낸다.
- 명단도 개인정보이므로 등록 정보와 같은 일정으로 파기한다.

### 6.6 공식 교육에서 쓰기 전 확인

- 개인정보처리자가 누구인지 정한다. 강사 개인이 운영하는지, 주관 기관이 운영하는지에 따라 동의 문안의 주체와 처리방침이 달라진다.
- 해외 사업자 클라우드(Supabase)에 실명·연락처를 두는 것이 괜찮은지, 처리위탁 고지가 필요한지 주관 기관 개인정보·정보보호 담당에 확인한다.
- 공공기관의 민간 클라우드 이용 기준(CSAP 등)은 개편 논의가 있어, 현재 적용 기준을 담당 부서에 확인한다.
- 기관에 이미 출석·이수 관리 시스템이 있으면 등록은 그쪽에 맡기고 이 앱은 등록 ‘끄기’로 운영한다.

## 7. 설문조사

설문지는 강사 계정에 템플릿으로 저장해 강의마다 붙여 쓰고, 결과는 차트와 엑셀로 받는다. 강의실이 파기돼도 템플릿은 남는다.

### 7.1 구성

- **템플릿**: 제목, 설명, 문항 목록. 강사 대시보드에서 만들고 복제·수정한다.
- **강의실에 붙이기**: 문항을 복사(스냅샷)해 저장한다. 템플릿을 나중에 고쳐도 지난 결과가 깨지지 않는다.
- **응답 시점**: 사전(입장할 때 등록 다음 단계), 중간(강사가 \[열기\]), 사후(강사가 \[열기\] 또는 종료 30분 전 자동 안내).
- **공개 방식**: 익명(기본, 만족도용)과 실명 연결(등록 정보와 연결, 사전 수준 진단용) 중 고른다. 실명 연결을 쓰려면 동의 문안의 목적에 ‘교육 효과 분석’을 추가해야 한다.
- **응답 규칙**: 1인 1응답. 설문이 닫히기 전까지는 제출한 답을 고칠 수 있다.

### 7.2 문항 유형

| 유형 | 설정 | 결과 표시 |
| --- | --- | --- |
| 단일 선택 | 선택지 2\~10개, ‘기타’ 직접 입력 | 막대그래프와 비율 |
| 복수 선택 | 선택지 2\~10개, 최대 선택 수 | 막대그래프 |
| 척도 | 1\~5 또는 1\~10, 양쪽 끝 라벨 | 분포와 평균 |
| 단답형 | 최대 100자 | 응답 목록 |
| 서술형 | 최대 1,000자 | 응답 목록, Markdown 내보내기 |

모든 문항에 필수 여부와 문항 설명을 넣을 수 있다.

### 7.3 결과

- **강사 화면**: 문항별 차트와 응답률(응답 수 ÷ 입장한 사람 수).
- **발표 화면 공유**: 강사가 고른 문항의 결과만 보여 준다. 서술형은 기본 비공개다.
- **엑셀**: 응답 시트(행 = 응답자, 익명 설문은 순번만)와 요약 시트(문항별 집계).
- **파기**: 응답은 등록 정보와 같은 일정(교육 종료 7일 후)으로 지운다. 필요한 결과는 그 전에 엑셀로 내려받는다.

퀵폴(5.3)은 강의 중 한 문항 즉석 투표이고, 설문지는 미리 만든 여러 문항 조사다. 둘은 테이블도 따로 쓴다.

교육생은 시작 후 24시간 동안 참여하고, 글·파일은 시작 72시간 뒤, 등록·설문 정보는 종료 7일 뒤 자동으로 지워진다. 강사는 그 전에 필요한 것을 내려받는다.

## 10. 데이터 모델

테이블은 10개다. 강의실 데이터는 모두 `room_id`로 묶여 강의실 단위로 파기하고, 강사 템플릿 2개만 강의실과 상관없이 남는다.

| 테이블 | 주요 필드 | 언제 지워지나 |
| --- | --- | --- |
| `rooms` | id, code(6자리), title, host\_id, status(draft·live·closed), registration\_mode(required·optional·off), collect\_phone, consent\_version, active\_ping\_id, started\_at, expires\_at, purge\_content\_at, purge\_pii\_at | 개인정보 파기 때(마지막) |
| `room_members` | room\_id, user\_id, nickname, color, joined\_at | 글·파일 파기 때 |
| `participants` | id, room\_id, user\_id, org, dept, name, phone, consent\_version, consent\_required\_at, consent\_optional\_at, roster\_id | 개인정보 파기 때, 또는 본인 삭제 즉시 |
| `rosters` | id, room\_id, org, dept, name, phone\_last4 | 개인정보 파기 때 |
| `nodes` | id, room\_id, ping\_id, parent\_id, type(ping·pong·reply·poll), author\_id, author\_nickname, is\_host, content, attachments, meta, is\_hidden, is\_closed, sort\_order, created\_at, updated\_at | 글·파일 파기 때 |
| `poll_votes` | node\_id, user\_id, option\_ids, created\_at | 글·파일 파기 때 |
| `room_surveys` | id, room\_id, template\_id, title, questions(스냅샷), timing(pre·live·post), anonymous, status, opens\_at, closes\_at | 개인정보 파기 때 |
| `survey_responses` | id, room\_survey\_id, user\_id, answers, submitted\_at | 개인정보 파기 때 |
| `ping_sets` | id, owner\_id, title, pings, updated\_at | 강사가 지울 때까지 |
| `survey_templates` | id, owner\_id, title, description, questions, updated\_at | 강사가 지울 때까지 |

### 10.1 규칙

- **트리 구조**: ping·poll은 parent\_id가 없고, pong의 parent는 ping, reply의 parent는 pong이다. 트리거로 강제한다.
- **ping\_id**: 모든 노드에 최상위 핑 ID를 채운다. 핑별 필터·가지 강조·내보내기를 재귀 쿼리 없이 처리하기 위해서다.
- **attachments**: `[{kind: image|file|link, url, thumb_url, name, mime, size}]`. 링크도 여기에 넣어 첨부 유형 필터를 한 방식으로 처리한다.
- **meta**: 퀵폴 설정 `{options: [{id, label}], multiple, show_results}`.
- **하나만 허용(유일성)**: 진행 중인 rooms.code, room\_members(room\_id, user\_id), participants(room\_id, user\_id), poll\_votes(node\_id, user\_id), survey\_responses(room\_survey\_id, user\_id).
- **인덱스**: 권한 규칙에 쓰는 컬럼(room\_id, user\_id, author\_id)에는 모두 인덱스를 건다.

### 10.2 설문 문항 JSON 예시

```json
[
```

## 11. 권한 규칙(RLS)과 보안

브라우저에는 접속 키가 그대로 드러나므로, 모든 테이블에 RLS를 켜고 만료·상태 검사도 서버 규칙에 넣는다. 화면에서만 막으면 API를 직접 호출하는 것을 막지 못한다.

| 대상 | 읽기 | 쓰기 |
| --- | --- | --- |
| `rooms` | 강사 본인, 입장한 참여자(공개 컬럼만 뷰로) | 생성·수정: 강사 본인 |
| `room_members` | 같은 강의실 참여자(닉네임·색상만) | `join_room` 함수로만 추가 |
| `participants` | 본인, 그 강의실 강사 | 본인 1회 등록(진행 중, 등록 모드 켜짐, 필수 동의 있음), 본인 수정·삭제 |
| `rosters` | 강사 | 강사 |
| `nodes` | 입장한 참여자(숨긴 글은 강사만) | ping·poll: 강사 / pong·reply: 입장한 참여자, 진행 중·만료 전, author\_id = 본인 / 내용 수정: 작성자 / 숨김·마감: 강사 |
| `poll_votes` | 본인 표만. 집계는 `poll_results` 함수 | 본인, 투표가 열려 있을 때 |
| `room_surveys` | 입장한 참여자 | 강사 |
| `survey_responses` | 본인. 강사는 `survey_results` 함수(익명 설문은 user\_id 제외) | 본인 1회, 설문이 열려 있을 때 |
| `ping_sets`, `survey_templates` | 소유 강사 | 소유 강사 |
| Storage `rooms/{room_id}/` | 공개 버킷(추측할 수 없는 경로) | 입장한 참여자, 버킷 크기·형식 제한 |

### 11.1 서버 함수(security definer)

- `join_room(code, nickname)`: 진행 중·만료 전인지 확인하고 room\_members에 추가한다.
- `register_participant(room_id, org, dept, name, phone, consents)`: 필수 동의가 없으면 거부한다. 선택 동의가 없으면 phone을 버린다.
- `poll_results(node_id)`, `survey_results(room_survey_id)`: 집계만 돌려준다.
- 파기는 함수가 아니라 Edge Function이 맡는다(12.2).

### 11.2 보안 체크리스트

- [ ] 공개 회원가입 끄기, 강사 계정은 대시보드에서 발급
- [ ] 익명 로그인 켜기 + Cloudflare Turnstile(보이지 않는 CAPTCHA)
- [ ] 익명 로그인 IP당 시간당 한도를 기본 30에서 300 정도로 상향(교육장 와이파이 공유 IP 대비)
- [ ] 모든 테이블 RLS 켜기, 로그인하지 않은 접근(anon 역할) 차단
- [ ] 만료·상태 검사를 RLS·함수에도 적용
- [ ] 링크는 http·https만 허용, 사용자 글을 HTML로 렌더링하지 않기
- [ ] 버킷 파일 크기 제한 10MB, 허용 MIME 목록 지정
- [ ] 휴대폰 번호 화면·엑셀 기본 가림 처리
- [ ] service\_role 키는 Edge Function에만 두고 프론트에 넣지 않기
- [ ] 입장 화면에 ‘개인정보·내부 자료 게시 금지’ 안내

## 12. 실시간 동기화와 파일 처리

실시간 메시지는 받는 사람 수만큼 집계되므로, 꼭 필요한 이벤트만 보내고 끊겨도 다시 맞추는 구조로 만든다. 파일은 썸네일로 전송량을 줄이고 Storage API로만 지운다.

### 12.1 실시간

- **채널**: 강의실당 1개(`room:{id}`).
- **이벤트**: 노드 추가·수정(숨김 포함), 강의실 변경(포커스·상태·만료 시각), 퀵폴 열림·마감, 설문 열림·닫힘.
- **방식**: 1단계는 Postgres Changes(room\_id 필터). 부하 테스트에서 지연·끊김이 보이면 Broadcast from Database(`realtime.broadcast_changes` 트리거 + 비공개 채널)로 바꾼다. 클라이언트는 `useRoomEvents` 훅 하나로 감싸 바꾸는 비용을 줄인다.
- **재연결**: 화면 복귀(`visibilitychange`)나 채널 재구독 때 마지막 `updated_at` 이후를 다시 조회한다. 휴대폰 화면이 꺼져도 글이 빠지지 않는다.
- **폴백**: 실시간 연결이 실패하면 5초 간격 증분 폴링으로 자동 전환한다.
- **퀵폴 집계**: 표마다 방송하지 않는다. 강사·발표 화면만 2초마다 `poll_results`를 호출한다.
- **접속자 수**: Presence 대신 room\_members 행 수로 센다(무료 플랜 Presence 한도가 낮음).
- **예비안**: 부하가 계속 넘치면 교육생은 포커스·상태 이벤트만 실시간으로 받고, 피드는 5초 폴링으로 가져온다. 글마다 모두에게 보내는 대상은 강사·발표 화면 2대로 줄어든다.

### 12.2 파일

- **경로**: `rooms/{room_id}/{uuid}.{ext}`, 썸네일은 `rooms/{room_id}/thumb/{uuid}.jpg`.
- **이미지**: 브라우저에서 원본(가로 1,280px, 약 500KB)과 썸네일(가로 400px, 약 40KB) 두 벌을 만든다. 피드·네트워크 뷰는 썸네일을, 눌렀을 때만 원본을 보여 준다. 무료 플랜에는 서버 이미지 변환이 없다.
- **문서**: 10MB 이하, 실행 파일은 버킷 MIME 설정으로 차단한다.
- **로딩**: 화면에 보일 때만 불러온다(지연 로딩).
- **삭제**: SQL로 `storage.objects`를 지우지 않는다(파일이 고아로 남고, 현재는 트리거가 거부함). pg\_cron이 매시간 Edge Function을 부르고, Edge Function이 Storage API로 폴더를 지운 뒤 DB 행을 지운다. 같은 호출에서 오래된 익명 계정도 정리한다.
- **전송량 부족 시**: 파일만 Cloudflare R2로 옮긴다(외부 전송량 무료).

## 15. 구현 단계

4단계로 나눠 만든다. 보안 규칙과 참석자 등록은 나중에 붙이면 모든 쿼리를 다시 손봐야 하므로 1단계에 넣고, 1단계는 부하 테스트를 통과해야 끝난다.

1. **1단계 기반(핵심 흐름 + 보안)**: 강사 로그인, 익명 로그인·Turnstile, 강의실 생성·시작·입장 코드·QR, 참석자 등록·동의, 텍스트 핑·퐁·리플 실시간, 포커스 동기화, 만료 검사(RLS), 재연결 다시 조회
   - 통과 기준: 가짜 교육생 60\~100명이 동시에 입장·게시해도 연결이 끊기지 않고, 새 글이 2초 안에 모든 화면에 나타남
2. **2단계 멀티미디어·운영**: 이미지(원본+썸네일)·파일·링크 첨부, 버킷 제한, 강사 숨김, 파기 Edge Function(글·파일 72시간, 개인정보 종료 7일), 3일마다 자동 호출
3. **3단계 발표·시각화**: 발표 화면, 네트워크 뷰, 필터, 퀵폴, 사전 명단 대조·출석부 엑셀, ZIP·Markdown 내보내기, 핑 세트 저장·가져오기
4. **4단계 설문**: 템플릿 편집기, 사전·중간·사후 열기, 응답·수정, 결과 차트, 엑셀

### 15.1 부하 테스트 방법

1. 대시보드에서 익명 로그인 IP 한도를 먼저 올린다. 테스트 스크립트도 한 IP에서 도는 현장과 같은 조건이다.
2. Node 스크립트로 supabase-js 클라이언트를 60·100개 만들어 각각 익명 로그인 → `join_room` → 채널 구독을 한다.
3. 20초 안에 모두 퐁을 1개씩 보내고, 각 클라이언트가 받은 글 수와 지연 시간을 기록한다.
4. Realtime 로그에서 한도 오류(`tenant_events`)와 연결 끊김을 확인한다.
5. 기준을 못 넘으면 12.1의 Broadcast 전환, 그래도 안 되면 폴링 예비안을 적용하고 다시 테스트한다.

## 16. 리스크와 대응

가장 큰 리스크는 강의 도중 한꺼번에 글이 쏟아질 때의 연결 끊김과, 개인정보를 다루는 데 따른 규정 문제다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 초당 메시지 한도 초과 | 일제히 게시할 때 연결 끊김 | 부하 테스트, Broadcast 전환, 폴링 예비안, 재연결 후 다시 조회 |
| 개인정보 유출 | 신뢰 하락, 법적 책임 | 최소 수집, RLS, 번호 가림, 자동 파기, 엑셀 관리 안내 |
| 공식 사용 규정 미충족 | 기관 교육에서 사용 제한 | 사전 검토(6.6), 등록 ‘끄기’로 운영 |
| 무료 프로젝트 일시정지 | 강의 당일 접속 불가 | 3일마다 자동 호출, 전날 점검 |
| 교육장 네트워크 차단 | 교육장 PC·와이파이에서 접속 불가 | 사전 테스트, 개인 노트북·핫스팟, 폴링 폴백 |
| 같은 IP 익명 로그인 제한 | 31번째 교육생부터 입장 실패 | 한도 상향 |
| 전송량 한도 초과 | 월중 이미지 로딩 실패 | 썸네일, 지연 로딩, R2 이전 |
| 부적절한 게시물 | 강의 분위기 훼손 | 강사 숨김, 입장 화면 게시 안내 |
| 휴대폰 화면 꺼짐 | 복귀 후 글 누락 | 복귀 시 다시 조회 |
| 한글 입력 중 Enter | 같은 글 두 번 등록 | `isComposing` 검사, 전송 중 버튼 잠금 |

## 17. 결정이 필요한 사항

1단계를 시작하기 전에 앞의 네 가지는 정해야 한다. 동의 문안과 등록 화면이 이 답에 따라 달라진다.

- [ ] 휴대폰 번호를 받을지, 받는다면 구체적인 용도(수료 안내 문자 등)
- [ ] 개인정보 보유 기간(제안: 교육 종료 후 7일). 기관 출석 자료 보관 기준과 맞추기
- [ ] 공식 업무용으로 운영할지, 강사 개인 도구로 쓸지(개인정보처리자·클라우드 검토 범위가 달라짐)
- [ ] 동의 문안에 넣을 개인정보처리자 이름과 문의처
- [ ] 리플 명칭: ‘리플’ 유지(권장) 또는 탁구 용어로 변경
- [ ] 퀵폴 결과를 교육생에게 실시간으로 보여 줄지, 마감 후에 보여 줄지(기본값)
- [ ] 강의실 연장 범위(최대 몇 시간까지)
- [ ] 서술형 설문 응답을 발표 화면에 공유할 수 있게 할지
